### Project Summary, Rationale, and Common Aspects

Software Engineering Fundamentals (SEF) is currently being taken by students with diverse backgrounds and programming experience. SEF is a core course in both programs (SE, IT). To accommodate such diversity, students will be assigned at random from a given project list, which is designed to allow for an agile or mixed approach for the first milestone and a more rigorous design for the second milestone using UML. We worked hard to come up with interesting and diverse projects to match your preferences. When working on the project, each team member should take into account the group's strengths, background, and interests. The project title will be drawn by the lecturer during the tutorial session and assigned to your team.

Assessment 1 (Milestone 1) is to understand the user requirements. These requirements describe what the user expects the system to do and the intended outcome. There are three perspectives to determine the user requirements:

- **Functional requirements** determine what the system should do, while the **non-functional requirements** describe how the system behaves and performs.
- **Use Case diagrams** express and outline the user's goals and expectations. Illustrate the activity flow of how the user interacts with the system and how the system responds to the user's action. To draw the diagrams, you can use any tools such as StarUML, UMLet, Lucid Chart, Miro, or Draw.io.
- **User Stories** describe the feature or functionality from the user's perspective by focusing on the "who," "what," and "why".

In addition, the timeframe and estimations for completing the project should be outlined utilizing a software engineering methodology (e.g. Scrum, Waterfall, Hybrid).

To achieve this, each group will need to work through the tasks consistently and will also need to form subgroups to allow all tasks to be completed in parallel. One or two persons should be responsible for proofreading the document before submission to ensure consistency in language and format. Remember to check that numbering is sequential when used and that all headings are formatted similarly at the same level. Headers and footers should also be the same throughout.

You will write a document of the software requirement specification (SRS) for your assigned topic. Please produce a professional report. You will be graded on the presentation of the report. You can find the SRS template below to guide you in writing the report.

> **Note:** As the Login and Logout functions will be frequent examples in the lectures and tutorials, team members are discouraged from using them as one of their identified use cases.

### Project titles: Business Analytics Application

The goal of this project is to create mobile-enabled analytics platforms that combine mobile app analytics, business intelligence (BI) tools, and market intelligence systems with real-time dashboard and reporting capabilities. The system should include user authentication and authorization, as well as a customizable dashboard with charts displaying KPIs, trend analysis, and drill-down features. The system can also generate reports with scheduling and sharing options. A real-time notification for anomalies or performance updates. Users can collaborate by commenting, annotating, or sharing dashboards within user groups.
